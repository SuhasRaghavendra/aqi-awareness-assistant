| D-025 | 2026-11-10 | Write bundle JSON with LF line endings and mark `artifacts/champion/** -text` in `.gitattributes` | Rely on the working tree's native line endings and on `core.autocrlf` | `MANIFEST.json` records SHA-256 digests of exact bytes. | D-026 | 2026-11-10 | Select the G4 classifier on validation metrics and report the gate on the holdout test split | Keep selecting the classifier with test metrics and report G4 on the same test set | The previous implementation chose the winner by test within-one rate and then measured that same split, so G4 evaluated its own selection set. | D-029 | 2026-11-12 | Raise the metamorphic per-row tolerance from 5% to 10% while keeping the mean-direction gates unchanged | Keep 5% and accept failing tests; drop the per-row gate; add monotone constraints now | The 5% gate was calibrated while `rebuild_features` silently median-filled every lag column. | D-030 | 2026-11-12 | **Pre-registered for Step 018.** Train a monotone-constrained LightGBM candidate (positive for fire features and fire interactions, negative for wind features) and restore the 5% metamorphic per-row tolerance | Keep the 10% waiver (D-029); drop the per-row gate | The 5% gate became unreachable because unconstrained trees can answer a fire increase with a small AQI decrease on individual rows. | D-031 | 2026-11-12 | **Pre-registered for Step 018.** Remediate G3 (Kolkata) on validation only, using a uniform mechanism applied to every city (per-city bias correction from inner-CV folds inside validation, plus a robust objective), then freeze the candidate and run test once | Patch Kolkata specifically; tune after the test result; change the 1.05 threshold | A Kolkata-only fix would encode the known test failure into the model. | D-032 | 2026-11-12 | Verify every bundle hash *before* unpickling, write all hashed artifacts atomically, and publish the champion through a staging-directory swap | Keep `joblib.load()` first and hope the file is intact; write directly to final paths; delete the old bundle before writing the new one | A partially written or tampered `bundle.joblib` is arbitrary code execution, so hash verification must precede deserialisation. `MANIFEST.sha256` → `MANIFEST.json` → every payload gives one chain of custody. | D-034 | 2026-11-12 | Derive hashed-artifact timestamps from the newest observation in the split; keep wall-clock latency percentiles out of the hashed risk card | Keep `SOURCE_DATE_EPOCH`/HEAD timestamps (D-027); keep latency numbers inside the risk card | Deriving from `HEAD` fails on the next commit and never converges; `dvc repro` then reports changed metrics forever.
